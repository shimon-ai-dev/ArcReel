# 从现有本地资产库导入 {#existing-library-bundles}

在原角色、场景资产面板导入既有人物与场景，不需要手写新的 JSON 清单，也不会建立另一套资产工作区。转换器先读取现有库的成品索引、归档确认记录和安全链接，生成便携目录；浏览器再上传这个目录中的已选媒体。

## 本地转换与预览 {#local-conversion}

在有权读取资产库、且已安装本分支 ArcReel 开发依赖的电脑上，从仓库目录运行：

```bash
uv run python -m scripts.book.prepare_library_bundle "/path/to/existing-library"
```

不传 `--output` 时只输出 JSON 预览，不创建文件。选择的路径必须是同时包含 `成品` 和 `characters` / `scenes` 归档的完整库根目录，不能只选成品子目录。

检查预览后，指定一个库外、尚不存在的输出目录：

```bash
uv run python -m scripts.book.prepare_library_bundle "/path/to/existing-library" \
  --library-id "my-character-library" \
  --output "/path/to/new-portable-bundle"
```

`--library-id` 是以后更新时保持不变的库标识；不传时默认使用根目录名。根目录改名或同名库并存时，应明确指定该标识。只处理部分现有成品入口时，可重复传入 `--entry person-9001 --entry scene-9002`。这些 ID 是示例，需替换成自己库中的入口目录名；源根目录仍必须包含归档。

成功时输出目录包含：

- `library-manifest.json`：自动生成的上传清单及相对来源路径。
- 以 SHA-256 命名的图片、音频：仅包含本次明确选择的媒体，同内容去重。
- `preview.json`：条目、来源证据、待定事项与警告，不需要上传。

回到原角色或场景资产面板，选择生成的目录，核对新增、更新、冲突与待定声音关系，再确认导入。也可单独选择清单和它引用的媒体文件。转换器不上传、不部署、不连接 NAS、不更新项目；最终项目写入发生在资产面板确认之后。

任何阻塞都会令命令退出码为 `2`；指定输出目录时只写 `preview.json`，不会留下可导入的清单或媒体。检查其中的文件位置、行号和原因，修正选择或补充脱敏格式样例后重新转换到另一个新目录。不要通过手改生成清单来绕过来源冲突。

## 支持的既有目录与记录 {#supported-layout}

入口是 `成品/人物/person-NNNN/索引.md` 和 `成品/场景/scene-NNNN/索引.md`。转换器只解析以下明确的现有表格和字段，不声称支持任意 Markdown、登记表或历史格式：

- 人物成品索引：`分类 / 文件 / 成品V / 精确来源版本 / 确认范围`。明确来源包含人物、`baseline`、`look`、`action`、归档版本及文件路径。图片确认记录位于 `characters/person-NNNN/packs/baseline-NNN_look-NNN_action-NNN/vNNN/approval.json`，采用 `files[].archive / product / sha256 / slot / width / height / frozen / user_confirmed`。
- 声音归档：`characters/person-NNNN/voices/voice-NNN/vNNN/approval.json`，人物、声音和版本分别使用 `person / voice / version`，逐文件使用 `files[].path / role / sha256`。明确选择的音频引用旁边，可嵌入已校验的同名逐字稿；逐字稿不作为额外上传文件。历史绝对 `product` 路径不作为读取路径。
- 人物登记 `character.md`：有匹配的 `包` 或 `声音设定` 行时，核对 `最后已批准版本` 链接；声音仅在 `适用 baseline` 单元格明确为单个 `baseline-NNN` 时标为已确定。写着“待定”或带未裁定说明的内容保持待定。
- 场景索引：支持 `成品文件 / 精确来源包与文件 / SHA-256` 的直接来源链接；也支持 `分类 / 文件 / 成品版本 / 确认范围 / 来源与记录` 指向 `scene-assets/asset-map.md`。后者必须由当前安全成品链接定位归档，再匹配地图中相应 `views/...` 文件段及 SHA-256。地图里失效的旧成品链接不代替当前入口。

明确的“当前推荐”及成品行决定选择，不按目录版本最大值或修改时间猜测。相同人物/基线/造型/动作或场景/状态仍出现多个版本、登记与索引冲突、格式无法确定时，停止打包并报告。场景显示入口可以引用另一场景的同一归档文件，导入保留归档所属场景 ID，不把显示分组当成原始身份。

## 安全与状态边界 {#safety}

- 原库只读。输出必须位于库外，且不覆盖现有输出目录。
- 成品符号链接仅可解析到同一所选库根目录内；越界、断链或不一致的文件立即阻塞。需要选择包含归档的完整根目录，而不是取消边界检查。
- 仅处理被选成品索引引用的图片、声音和配对逐字稿。不扫描工作候选，不复制 `source_candidate`、凭据、完整索引文档或其他无关文件。
- 人物 ID、基线、造型、动作、场景状态、归档版本与成品版本互不替代。`action-000` 作为普通静态动作标识保留。
- 单文件确认、单文件冻结和整包批准分别保留。场景包即使已 `validated`，也不因此变成已批准；不从“图片可解码”或哈希匹配推导用户确认。
- 声音技术通过、已试听、模型适配和克隆验收是不同字段。声音基线待定时输出独立声音条目，不自动套用人物图片基线；导入预览会继续呈现这个限制。
- 不删除源库或项目中缺失的旧引用。项目端对同一冻结版本禁止覆盖，显式升级到不同版本须经过预览并保留历史。

## 验证范围与限制 {#validation}

图片支持 PNG、JPEG、WebP，最多 4000 万像素；声音支持非空单声道或双声道 PCM WAV。每个文件最多 20 MiB，每包最多 200 个媒体文件、128 MiB。大库可用 `--entry` 分批选择，且每次使用新输出目录。

转换时核验源 SHA-256、图片尺寸与可解码性、音频完整性，写出时再次核验内容；项目导入预览和正式写入还会重新校验。哈希校验不等于图像一致性、声音克隆效果或素材授权已获验证。

实现由虚构 ID、临时目录和合成媒体测试覆盖。真实库的所有登记方言、用户电脑实际路径、NAS 挂载、模型生成效果与真人试听不在这些测试的验收结论内。遇到未知方言应先提供最少量的脱敏索引/确认记录，不需要发送凭据、完整台账或私人素材来解释结构。
