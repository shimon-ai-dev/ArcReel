# 本地 VOX 声音适配 {#voxcpm2}

VoxCPM2 用于角色人声，不替代章节拆解、人物资产或场景音轨。内置大模型分析的台词、说话人和表演意图仍属于原有章节工作流；正文和表演描述分别保存。雨声、脚步、开门等环境／动作声音使用独立素材和时间线，不送给人声模型假装已经生成。

## 两种克隆方式 {#cloning}

- **可控克隆**：以参考声音保持音色，使用自然语言描述情绪、语气和表达方式。适合同一角色在不同剧情中的表演。
- **续接克隆**：参考声音必须配有准确逐字稿，优先延续参考中的韵律、情绪和风格。这个模式不同时使用额外表演描述，避免把两个不同控制方式混在一起。

VOX 的表演描述不是 IndexTTS 的八维情绪向量，也不是精确的语速、情绪强度滑块。可控克隆在调用官方模型时按官方格式把描述放入文本开头的括号；存储的原文不改动。该约定不保证模型永远不会误读描述，仍需试听。精确数值语速／情绪强度、原生喘息／哭笑标签没有在适配器中宣称为已支持，请求这些控制会报错而非忽略。表达强弱或快慢可用自然语言提出，但执行效果不是确定性保证。段间停顿由音频时间线添加静音，不依赖模型猜测。

## 部署边界 {#deployment}

此功能连接仓库提供的可选 `scripts/book/vox_bridge.py`，不是假定任意 VOX 服务都有相同 HTTP 协议。已使用其他部署封装时，应先核对它的接口，不要直接填入地址期待兼容。

在自行准备好的官方 VoxCPM2 环境中运行桥接，模型目录必须是本地已存在的 VoxCPM2 权重。桥接不下载模型，不创建凭据，不在导入时启动服务。参考目录只读。复用原有人物声音资产时，将参考根目录指向 ArcReel 的 projects 目录（独立进程／容器须只读挂载同一份目录），服务会发送“项目名/项目内音频路径”。手工配置的声音路径仍相对该根目录，不自动添加项目名；越界、缺失和符号链接会被拒绝。

```bash
PYTHONPATH=/path/to/ArcReel:$PYTHONPATH python /path/to/ArcReel/scripts/book/vox_bridge.py \
  --model-dir /path/to/VoxCPM2 \
  --reference-root /path/to/ArcReel/projects \
  --port 7862
```

桥接只监听 `127.0.0.1`。这不是一套公开网络服务的鉴权方案；NAS 与模型分处不同机器时，需要部署者另行配置受保护连接，不能直接暴露公网。角色配置使用 `voxcpm2` 适配器、显式的 VoxCPM2 模型和桥接地址。参考音频须拥有使用权。续接模式还需填写参考逐字稿；模式和生成参数保存在该声音配置中，改变后会使对应语音缓存失效。

桥接核对模型架构并使用原生 48 kHz 采样率输出 WAV，不把旧型号或其他服务的结果冒充 VoxCPM2。固定种子帮助复查同一设置，不保证跨硬件、模型版本和运行库逐比特一致。绑定原有人物资产的声音会校验参考文件内容摘要；同名文件替换也会要求重新同步并使对应语音缓存失效。手工配置的独立声音仍须自行更新摘要，仅复用同名路径不能证明内容没有改变。

## 效果验收 {#acceptance}

必须使用实际参考声音测试普通说话、常见情绪、停顿、拉长音和非语言表现，并检查跨句音色稳定、正文完整、指令未被读出。喘息、哭笑等可以作为自然语言表达意图探索，但不能因为提交成功就标为支持或达标；不可靠时保留明确失败／欠佳结论，或使用经授权的声音素材，不能静默换模型或声线。

仓库测试验证协议映射、能力拒绝、48 kHz 编码、路径限制和失败传播，未运行本地 VOX 模型，也未验收真人还原效果。

官方能力与参数依据：[VoxCPM 项目](https://github.com/OpenBMB/VoxCPM)、[Python 接口](https://github.com/OpenBMB/VoxCPM/blob/main/src/voxcpm/core.py)、[CLI 克隆模式约束](https://github.com/OpenBMB/VoxCPM/blob/main/src/voxcpm/cli.py)。
